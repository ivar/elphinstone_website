# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build Commands

- `npm run dev` — Build CSS in watch mode + start Hugo dev server (via `concurrently`)
- `npm run build` — Refresh the species list from iNaturalist and the task lists from OpenProject, build CSS with Tailwind CLI, then Hugo production build
- `npm run species` — Refresh `data/species.json` from iNaturalist only
- `npm run course` — Encrypt `courses/*.html` into the password-protected course pages under `static/` (needs `COURSE_PASSWORD` in the environment or `.env.local`)
- `npm run tasks` — Refresh `data/tasks.json` from OpenProject only (needs `OPENPROJECT_TOKEN` in the environment or `.env.local`)

## Architecture

Static landing page for Elphinstone Farm built with Hugo + Tailwind CSS v4 + DaisyUI v5. No frontend framework.

- **`hugo.toml`** — Hugo site configuration (baseURL, title, disabled kinds)
- **`layouts/_default/baseof.html`** — Base HTML template (head, body wrapper, CSS link)
- **`layouts/index.html`** — Home page template (extends baseof; logo, hero, cards, footer)
- **`assets/css/style.css`** — Tailwind v4 source CSS (input to Tailwind CLI)
- **`static/images/`** — Static assets (logo.png, footer.png, logo.svg)
- **`static/fonts/`** — Self-hosted variable font woff2 files (Fraunces, Nunito)
- **`static/css/style.css`** — Built CSS output (generated by Tailwind CLI; gitignored)
- **`content/_index.md`** — Home page front matter (required by Hugo)
- **`content/projects/`** — Projects section: `_index.md` (list intro) plus one page bundle per project (`<slug>/index.md` + photos). Front matter: `color`, `icon`, `status`, `summary`, `intention`, `cover`, `updates[]` (date, title, text, why, photos[src, alt, caption]). Body = educational copy.
- **`layouts/projects/`** — `list.html` (grid of `partials/project-card.html`) and `single.html` (intention card, glossary-style body, photo timeline via `partials/project-photo.html`). Photos are looked up by `partials/project-image.html`: page bundle first, then fetched at build time from the R2 bucket at `<params.mediaBaseURL>/<project-folder>/<src>` and resized by Hugo
- **Species page** — `content/projects/species/index.md` uses `layout: species` (`layouts/projects/species.html`). Its data is `data/species.json`, generated by `scripts/fetch-species.mjs` (`npm run species`, also run by `npm run build`) from iNaturalist observations inside `data/property_boundary.json`. The JSON is committed as a fallback for when iNaturalist is unreachable; species photos are fetched and resized by Hugo at build time.
- **Next tasks** — a project page with `openproject: ["<identifier>"]` in its front matter (optionally `tasksMatch` / `tasksExclude` title regexes) shows the open tasks of those OpenProject projects and their subprojects. `scripts/fetch-tasks.mjs` (`npm run tasks`, also run by `npm run build`) reads them from https://tasks.elphinstone.farm (API v3) into `data/tasks.json`, keyed by page folder name; only title, priority and dates are kept, since the file is public. It is committed as a fallback for builds without a token.
- **Password-protected course** — `/projects/agrivoltaics-and-power/home-power-basics/` is a standalone page linked from the project's `courses:` front matter. The readable source is `courses/home-power-basics.html` (outside the folders Hugo publishes). **Edit that file, never the one in `static/`**, then run `npm run course`: `scripts/encrypt-course.mjs` encrypts it (AES-256-GCM, PBKDF2 key from `COURSE_PASSWORD`) into `static/projects/agrivoltaics-and-power/home-power-basics/index.html`, a password form that decrypts in the browser. Commit both files. The password only deters casual browsing (the source is in this public repo), but keep it out of the repo. Production builds have no password and just publish the committed encrypted page, so always run `npm run course` before committing a course edit.
- **Projects map** — `layouts/partials/property-map.html`, shown at the top of `/projects/`: an overhead photo with a linked marker for each project that has `location` (`x`, `"y"` in % of the photo, optional `label: "left"`) in its front matter. Keep the `"y"` key quoted: unquoted, older Hugo versions (such as the one that builds production) read it as a YAML boolean and every marker lands at the top. The photo is `assets/images/property-overhead.*` if present; otherwise the SCRD 2024 aerial photo for the area in `params.propertyMap` (`hugo.toml`) is fetched at build time and the property boundary is drawn over it. In `hugo server`, clicking the photo prints a `location` snippet.
- **`archetypes/projects.md`** — template for `hugo new projects/<slug>/index.md`

## Styling

Uses Tailwind CSS v4 syntax (`@import "tailwindcss"`, `@plugin`, `@theme` directives). DaisyUI components (`card`, `btn`, `hero`, `join`) are used throughout.

The custom `elphinstone` DaisyUI theme is defined in `assets/css/style.css` and activated via `data-theme="elphinstone"` on `<html>`. Colors use OKLCH and represent the landscape: primary=mountain teal, secondary=forest green, accent=golden sun. Main text color is `#404949`.

**Fonts:** Fraunces Variable (serif, headings) and Nunito Variable (sans-serif, body) — self-hosted as woff2 variable fonts in `static/fonts/`, sourced from `@fontsource-variable` npm packages. `@font-face` declarations are in `assets/css/style.css`. No external font dependencies. Base font size is 125%.

## CSS Build Pipeline

Tailwind CSS v4 CLI processes `assets/css/style.css` and outputs to `static/css/style.css`. Hugo then copies `static/css/style.css` into the built site unchanged. The Tailwind CLI automatically scans `layouts/` for class names.
